# sandustry-native

Нативное ядро симуляции для Sandustry: то же, что делает её `updateElementCell`,
но в нативном коде и над той же разделяемой памятью.

Задача узкая — играть без просадок. По замерам игры 84 % времени тика уходит на
обход клеток, и упирается он не в алгоритм (он там хороший), а в цену каждого
обращения к данным в V8.

## Что уже есть

- `crates/sand-sim` — ядро: движение сыпучего и жидкостей, вытеснение по
  плотности, отбор чанков, очередь событий. Не знает ни про Node, ни про WASM:
  чистая логика над срезами, поэтому гоняется в тестах без запуска игры.
- `crates/sand-bench` — замер на снимке настоящего мира.
- `crates/sand-node` — обёртка N-API: массивы игры приходят видами над её
  разделяемой памятью, копирования нет ни на входе, ни на выходе.
- `js/smoke.js` — проверка модуля без запуска игры: песок падает, изменения
  видны в исходных массивах JS, чанки с хуками и структурами возвращаются.

```bash
cargo build --release -p sand-node && cp target/release/libsand_node.dylib js/sand.node
node js/smoke.js
```

## Замеры

Снимок 320×320 из живого мира, 91 100 элементов, 93 % заполнения:

| | на клетку |
|---|---|
| Sandustry (по её же профайлеру) | ~132 нс |
| это ядро | **8.5–10 нс** |

Разрыв порядка 13–15×. Оговорка: ядро пока не проверяет зоны авторизации,
блок-сетку структур и маски мод-хуков — с ними цена вырастет.

```bash
cargo test -p sand-sim
cargo run --release -p sand-bench -- fixtures/busy-320.json 300
cargo run --release -p sand-bench -- fixtures/busy-320.json 300 --carve
```

`--carve` вырезает в снимке полость: плотно забитая сцена меряет в основном
холостой скан, а с полостью масса обрушивается и видно цену настоящей работы.

## Границы

Ядро считает только то, за что отвечает целиком. Всё остальное — элемент с
мод-перехватчиком, соседняя структура, незнакомое состояние материи — уходит
наружу событием `NeedsJs`, и досчитывает это старый код игры. Так моды остаются
рабочими, а поведение не разъезжается втихую.

Побочные эффекты (растр, звук, экономика, события модов) ядро не вызывает — оно
копит их в очереди, а применяет принимающая сторона одним проходом после тика.
Иначе переходы между мирами съели бы весь выигрыш.

## Отбор чанков

Ядро берёт чанк, только если отвечает за него целиком: все типы элементов есть
в таблице материи, ни на один не подписан мод-перехватчик, рядом нет структуры.
Обе маски игра и так держит в разделяемой памяти, так что решение стоит чтения
пары байтов — ни одного вызова в JS.

Чанк, который не прошёл отбор, возвращается нетронутым с указанием причины, и
его считает старый код. Счётчики по причинам доступны через `stats()`: по ним
видно, окупается ли затея на живом мире.
