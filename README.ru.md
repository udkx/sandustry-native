# sandustry-native

Нативное ядро симуляции для **Sandustry 0.5.2**: то же, что делает её
`updateElementCell`, но в нативном коде и над той же разделяемой памятью.

Задача узкая — играть без просадок, не переписывая игру. По замерам игры 84 %
времени тика уходит на обход клеток, и упирается он не в алгоритм (он там
хороший), а в цену каждого обращения к данным в V8.

> **Экспериментально.** Патчится купленная вами игра. Оригинал сохраняется, патч
> снимается одной командой — но это сборка для тестирования, а не мод, который
> ставят и забывают.

## Что это даёт

Один сейв, одна камера, один запуск: ядро включается и выключается фазами по 30
секунд, поэтому обе ветки меряются на одной сцене.

| | с ядром | без ядра |
|---|---:|---:|
| тик, медиана | **9.9 мс** | 21.0 мс |
| тик, p95 | 15.7 мс | 27.4 мс |
| обновлений симуляции в секунду | 58.9 | 46.3 |
| загрузка воркеров | 42 % | 82 % |

Бюджет тика — 16.67 мс. На обжитом сейве игра без ядра тратит 21 мс и не держит
60 ups; с ядром тик укладывается в бюджет вместе с хвостом, а воркеры простаивают
больше половины времени вместо того, чтобы упираться в потолок.

## Установка

Нужны Sandustry 0.5.2 из Steam и Node.js 18+.

1. Скачайте ядро для своей платформы из [релизов](../../releases) в каталог
   `prebuilt/`.
2. Дальше:

```bash
npm install
node installer/install.js
```

Установщик сам находит игру в библиотеке Steam, сохраняет `app.asar` рядом с
собой, патчит внутри него два файла и кладёт ядро рядом с ресурсами игры. Если
автопоиск не сработал, укажите каталог руками:

```bash
node installer/install.js --game "путь к каталогу игры"
```

Запускайте игру как обычно — ядро включается само.

Снять:

```bash
node installer/install.js --revert
```

Откат возвращает сохранённую копию `app.asar` байт в байт, а не пытается
отменить патч. Если что-то пошло не так раньше — «Свойства» → «Установленные
файлы» → «Проверить целостность» в Steam восстановит игру.

## Моды выключены, пока работает ядро

Воркер симуляции может загрузить нативный модуль только при
`nodeIntegrationInWorker`, а этот флаг даёт доступ к Node **всему, что в этих
воркерах исполняется, — включая моды Workshop**. Мод получил бы файловую систему
целиком.

Поэтому одно исключает другое:

| запуск | ядро | моды Workshop |
|---|---|---|
| обычный | работает | **выключены** |
| `--with-mods` | выключено | работают |

Чтобы играть с модами, добавьте в Steam → «Свойства» → «Параметры запуска»:

```
%command% --with-mods
```

Игра пишет первой строкой лога, в каком режиме стартовала.

## Если что-то сломалось

Мост пишет строку в `sandustry-native.log` во временном каталоге системы
(`%TEMP%` на Windows, `/tmp` на macOS и Linux). Приложите этот файл и сейв к
issue — без них диагностировать нечего.

Свой замер снимается так: задайте длину фазы в секундах, встаньте на месте и не
двигайте камеру.

```bash
SANDUSTRY_NATIVE_AB=30 <запуск игры>
```

Все воркеры считают фазу по общим часам, поэтому переключаются синхронно без
единого сообщения между собой. В логе появится разбивка времени по фазам: ядро,
растр, досчёт клеток, чанки, отданные обратно в JS.

## Из чего состоит

- `crates/sand-sim` — ядро: движение сыпучего и жидкостей, вытеснение по
  плотности, отбор чанков, очередь событий. Не знает ни про Node, ни про игру:
  чистая логика над срезами, поэтому гоняется в тестах без запуска чего-либо.
- `crates/sand-node` — обёртка N-API: массивы игры приходят видами над её
  памятью, копирования нет ни на входе, ни на выходе.
- `crates/sand-bench` — замер на снимке настоящего мира.
- `installer/` — поиск игры, патч `main.js` и воркера, установка ядра, откат.
- `js/smoke.js` — проверка модуля без запуска игры.

```bash
cargo test -p sand-sim
cargo run --release -p sand-bench -- fixtures/busy-320.json 300 --carve
```

Снимка `fixtures/busy-320.json` в репозитории нет: это 41 МБ данных самой игры.
Тестам он не нужен, а для бенчмарка снимок снимается из запущенной игры.

`--carve` вырезает в снимке полость: плотно забитая сцена меряет в основном
холостой скан, а с полостью масса обрушивается и видно цену настоящей работы.

## Границы

Ядро считает только то, за что отвечает целиком. Всё остальное — элемент с
мод-перехватчиком, соседняя структура, незнакомое состояние материи, истёкший
таймер — уходит наружу событием `NeedsJs`, и досчитывает это старый код игры.

Побочные эффекты (растр, звук, экономика, события модов) ядро не вызывает — оно
копит их в очереди, а применяет принимающая сторона одним проходом после тика.
Иначе переходы между мирами съели бы весь выигрыш: замер показал, что один
слишком широкий признак «эта пара реагирует» отправлял в JS 57 % обойденных
клеток и делал игру с ядром **медленнее** оригинала на 26 %.

Негласные соглашения игры, которые обязан соблюдать любой, кто двигает её
клетки, собраны в [`docs/game-contracts.md`](docs/game-contracts.md). Каждое
стоило цикла отладки в живом мире.

## Чего пока нет

- Только Sandustry 0.5.2 из Steam.
- Чанк, рядом с которым стоит машина, целиком отдаётся старому коду: это 28 %
  неспящих чанков и 73 % оставшегося времени. Следующая работа — гейт по клетке
  вместо гейта по чанку.
- Не воспроизведён `margin` обхода: игра сдвигает окно чанка, чередуя границы
  между потоками, а ядро считает чанк по его границам. Поведение на стыках полос
  потоков немного отличается от оригинала.

## Правовое

В репозитории **нет кода и ресурсов Sandustry**. Здесь отдельная нативная
библиотека и патчер, который правит вашу собственную копию игры на вашей машине
— ровно то же, что делает любой загрузчик модов.
